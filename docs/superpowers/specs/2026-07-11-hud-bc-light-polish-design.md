# HUD BC-L 摘要布局精修设计

## 背景

当前 HUD 已具备摘要、列表和分页三种布局，摘要布局采用 hero 指标加滚动列表。下一轮视觉优化选择 BC-L 方向：保留动态岛式轮廓和轻量弹性动效，同时吸收数据仪表的数字对齐、信息层级与紧凑表达。

本轮只精修默认的摘要布局。列表、分页、收起态、provider 数据结构及浮窗生命周期不在范围内。

## 目标

- 强化摘要布局的主次层级，让 hero 指标更容易扫描。
- 统一数字排版和右侧对齐，获得轻量仪表感。
- 增加克制的展开入场动效，不干扰实时数据刷新。
- 只展示现有模型提供的真实信息，不推断趋势或额度健康状态。
- 尊重 macOS“减少动态效果”辅助功能设置。

## 非目标

- 不增加历史趋势、更新时间或新的 provider 状态字段。
- 不显示推断得到的 `OK`、`LOW` 等状态标签。
- 不修改列表布局、分页布局或收起态刘海。
- 不修改 widget 存储、`state.json` schema、拉取器或凭据流程。
- 不引入循环呼吸、扫光或持续运行的装饰动画。

## 视觉结构

### Hero

Hero 顶行调整为三段式结构：provider 图标、平台与指标名称、右侧主数值。主数值使用圆角等宽数字并右对齐。现有 `formattedDetail` 等真实辅助信息显示在主数值下方；辅助信息为空时不保留占位高度。

进度条位于 hero 顶行下方，继续使用 provider 强调色。高占用状态可保留低强度静态辉光，但不得盖过主数值或产生持续动画。

### 普通行

普通行保持图标、名称、数值三列。数值列使用稳定的最小宽度、等宽数字和右对齐，避免数值刷新造成横向跳动。已有辅助详情显示在数值下方，不增加推断标签。

### 表面与颜色

继续使用现有 notch 深色表面和 provider 强调色映射，不增加新的全局颜色体系。BC-L 的仪表感来自排版与信息层级，而不是更强的边框、辉光或高饱和装饰。

## 动效

### 展开入场

- Hero 先进入。
- 普通行按索引依次淡入并轻微上移，行间延迟约 20 至 30 毫秒。
- 整组入场控制在约 250 毫秒内，使用克制的缓动，不增加明显弹跳。
- 入场只由摘要布局从收起到展开触发；实时数据变化不得重播整组动画。

### 数据更新

- 主数值和普通行数值继续使用数字滚动过渡。
- 进度条宽度使用短促平滑的变化动画。
- 数据更新不得改变行高、数值列宽或触发整行位移。

### 辅助功能

读取 macOS 的 `accessibilityReduceMotion` 环境值。开启“减少动态效果”时，关闭行位移和错位延迟，只允许快速透明度变化；数字和进度变化不得产生大幅空间运动。

## 组件边界

改动集中在摘要布局使用的现有组件：

- `OverlaySummaryView`：控制展开入场状态和普通行顺序。
- `OverlayHeroRow`：调整 hero 三段式层级和辅助信息位置。
- `OverlayListRow`：统一数值列宽度与对齐。
- `UsageBar`：保留轻辉光并增加短促宽度过渡。

不为本轮建立新的数据层抽象。只有当动效状态无法在现有视图中清晰隔离时，才允许新增摘要布局内部的私有 ViewModifier；不得扩大为全局动画系统。

## 数据与异常处理

所有文本继续来自 `WidgetMetricComputer`。若数值或辅助信息缺失，沿用现有格式化与回退逻辑。视图不得自行判断额度健康状态，也不得根据颜色推导业务含义。

Widget 列表为空时保持当前空状态行为。快速增删或排序 widget 时，布局应稳定更新，不崩溃、不重复播放完整展开动画。

## 验证

### 自动验证

- 运行 `swift test`，确保核心格式化与几何测试无回退。
- 运行 `xcodebuild -project token_hud.xcodeproj -scheme token_hud -destination 'platform=macOS' build`，确保 app 完整编译。
- 如提取了可测试的纯动效策略或布局计算，再补充聚焦测试；不为 SwiftUI 装饰性动画强行增加脆弱快照测试。

### 手动验证

- 摘要布局展开时，hero 先进入，普通行错位入场自然且总时长不拖沓。
- 实时数据频繁刷新时，只更新数字和进度，不重复播放整组入场。
- 有无 `formattedDetail` 时 hero 和普通行都不出现无意义空白。
- 不同 HUD 缩放比例下文字不截断，数值列不跳动。
- 开启“减少动态效果”后无明显位移或错位动画。
- 高占用辉光不过曝，不影响文字和进度条辨识。

## 风险与控制

- 展开状态来自窗口生命周期，若视图无法准确判断一次展开周期，可能导致动画重复。实现时应复用已有展开进度或显式传入稳定状态，避免根据数据刷新推断展开。
- 固定数值列过宽会压缩名称，过窄会导致长金额截断。实现时使用缩放后的最小宽度，并保留 `minimumScaleFactor` 与单行限制。
- 行级延迟可能在 widget 很多时拖长动画。延迟需要设置上限，保证整组在约 250 毫秒内完成。
- 当前工作区已有未提交的 HUD 改动。实现和提交必须保留并基于这些改动继续，不得覆盖或重置。
